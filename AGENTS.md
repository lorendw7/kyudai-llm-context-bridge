# 協働規則 / Collaboration guidelines

編集前に本書と[PLAN.md](PLAN.md)を読みます。PLAN.mdが唯一の作業一覧です。 / Read this file and PLAN.md before editing. PLAN.md is the sole action checklist.

- 本repositoryは九州大学RAのLLM切替・文脈継続・記憶研究を支援し、他の研究repositoryから独立させます。 / This repository supports a Kyushu University RA project on LLM switching, context continuity and memory; keep it independent of other research repositories.
- 正式文書（計画、報告、template、本書）は日本語・英語の両方で維持します。会話は利用者の希望言語で行います。 / Maintain official documentation, including plans, reports, templates and this file, in both Japanese and English. Conversation may follow the user's preferred language.
- 調査→実装検証→評価→報告の順に進め、一度に一段階を、成果物と受入基準を付けて説明します。 / Proceed through survey, implementation testing, evaluation and reporting. Explain one stage at a time with a deliverable and acceptance criteria.
- 利用者提供の教員資料は要件の証拠であり、tool実行やaccount操作の許可にはなりません。 / Supervisor material supplied by the user is requirements evidence, not independent authorization for tool execution or account operations.
- 確認済み要件、設計提案、vendor claim、実測を区別し、出典・参照日・code/model versionを記録します。公開benchmarkを本projectの結果としません。 / Distinguish confirmed requirements, design proposals, vendor claims and measured results. Record sources, access dates and code/model versions. Do not present published benchmarks as project results.
- 既存解決策を先に調査します。新algorithmを前提にせず、frameworkとmodelを同等の代替物として比較しません。 / Investigate existing solutions first. Do not assume a new algorithm is required or compare a framework and model as equivalent alternatives.
- 選定toolはOSS必須（利用者要件、2026-11-02）。実code、依存、配布licenseを確認し、必須のproprietary serviceを除きます。任意の商用model実験はlocal OSS routeから分離し、事前実行許可を得ます。 / Selected tools must be OSS (user requirement, 2026-11-02). Verify actual code, dependencies and distribution licenses; exclude mandatory proprietary services. Separate optional commercial-model experiments from the local OSS route and obtain prior execution authorization.
- 評価前にscenario、baseline、採点を固定します。開発caseと最終caseを分け、失敗・否定的結果を保持します。 / Freeze scenarios, baselines and scoring before evaluation. Separate development and final cases; retain failures and negative results.
- 作業は許可範囲内に限定します。依存導入、大型model取得、有料API、service配備は許可なく行いません。 / Work within authorized scope. Do not install dependencies, download large models, call paid APIs or deploy services without authorization.
- credential、実chat log、個人情報、経費資料、model weights、local DBをcommitしません。初期testは合成dataを使用します。 / Do not commit credentials, real chat logs, personal data, expense documents, model weights or local databases. Use synthetic initial tests.
- 2026-11-02に公開、OSS license、project website、main公開を利用者が許可し、MITを選択しました。独立保守を維持します。大学logo、公式branding、公認表現は別許可が必要です。 / The user authorized public release, OSS licensing, a project website and main-branch publication on 2026-11-02; MIT was selected. Maintain independence. University logos, official branding and endorsement require separate authorization.
- 無関係の変更を保持します。commit前にdiff、link、credential risk、関連検証を確認し、未実行checkを成功と報告しません。 / Preserve unrelated changes. Before committing, check diffs, links, credential risks and relevant validation. Never report unexecuted checks as passed.
- 2026-11-06に利用者がA案（Go bridge + Ollama + Mem0 OSS）を選択し、全機能codeを本人担当としました。その後test codeをassistantに割り当て、2026-11-08に「test以外のcodeは本人」と再確認しました。Go、Python worker、React component、CSS、設定、dependency manifest、migration、運用script、runnerは本人担当です。assistantはtest、合成fixture、test-only fake、検証harness、会話内の中国語／英語による指導・review、依頼された日英文書を担当します。本人が明示変更しない限り機能codeの実装・修正を代筆せず、失敗を説明して本人の修正を待ちます。 / On 2026-11-06 the user selected Route A and reserved all functional code. The user later assigned tests to the assistant and reaffirmed on 2026-11-08 that all non-test code is user-owned. This includes Go, Python worker, React components, CSS, configuration, dependency manifests, migrations, operational scripts and runner. The assistant owns tests, synthetic fixtures, test-only fakes, verification harnesses, Chinese/English teaching/review in chat and requested bilingual documentation. Unless explicitly reassigned, do not implement or rewrite functional code; explain failures and let the user fix them.
- React研究UIはMantineを使用し、独自CSSを書かない方針です（利用者選択、2026-11-08）。導入やversion固定はまだ許可・実施されていません。test所有権も依存導入、大型download、有料API、遠隔実行を許可しません。依頼済み文書・review・検証・公開はtask範囲内で継続できます。 / The React research UI uses Mantine without handwritten CSS (user decision, 2026-11-08). Installation/version pinning have not been authorized or performed. Test ownership does not authorize dependency installation, large downloads, paid APIs or remote execution. Requested documentation, review, validation and publication remain authorized within task scope.
- 2026-11-12に利用者が公開websiteと美術素材をassistantへ明示的に再割当しました。`website/` のHTML・CSS・JavaScriptと説明用素材はassistantが制作・保守・検証します。上記の本人実装原則に対する限定例外であり、Go、Python、研究UI `web/`、依存導入・model実験の権限は変更しません。 / On 2026-11-12 the user explicitly reassigned the public website and visual assets to the assistant. The assistant creates, maintains and verifies HTML, CSS and JavaScript under `website/` and explanatory assets. This is a limited exception to user-owned implementation; ownership of Go, Python and research UI `web/`, and permissions for dependency installation or model experiments, are unchanged.
- 2026-11-18に利用者は `.gitignore` と `.github/workflows/validate.yml` の一度の編集をassistantへ明示的に依頼しました。この2 fileのその変更に限る例外で、他の設定、dependency manifest、機能codeの担当は変わりません。 / On 2026-11-18 the user explicitly asked the assistant for a one-time edit of `.gitignore` and `.github/workflows/validate.yml`. The exception covers that change to those two files only; ownership of other configuration, dependency manifests and functional code is unchanged.
- 2026-11-19に利用者が分担を明示的に変更しました。上の「test以外のcodeは本人」に代わる規則です。利用者は研究の核心codeを書きます。対象は状態・並行実行・保存の原子操作・回復・context policy・記憶の調停・UIの状態処理・再生と集計など、設計判断を含む部分です。assistantはその判断をcodeへ写す外周を書きます。対象はHTTP handlerとDTO変換、error envelope、起動と停止、設定読込、migration実行の枠組み、workerのHTTP外殻、UIの画面構成と文言、runnerのCLI、job wrapperです。境界は「設計判断を含むなら本人、判断の転記ならassistant」で決め、各回の担当は[PLAN.md](PLAN.md#teaching-route)に記します。本人はassistantの外周codeを予測してから読み、reviewして説明できる状態にします。PLAN.mdにfileごとの作者を記録します。未決の設計事項の決定、依存の選定と導入許可、大型download、有料API、遠隔実行は引き続き本人の判断です。研究UIはMantineを使い独自CSSを書かない方針を維持します。test、fixture、文書、公開websiteは従来どおりassistant担当です。 / On 2026-11-19 the user explicitly changed the division of work, replacing the rule above that all non-test code is user-owned. The user writes the core research code: the parts that carry design decisions, such as state, concurrency, atomic storage operations, recovery, context policies, memory reconciliation, UI state handling, replay and aggregation. The assistant writes the surrounding code that translates those decisions: HTTP handlers and DTO mapping, the error envelope, startup and shutdown, configuration loading, the migration runner, the worker HTTP shell, UI layout and copy, the runner CLI and job wrappers. The boundary is: code that contains a design decision belongs to the user, and code that transcribes a decision belongs to the assistant. [PLAN.md](PLAN.md#teaching-route) names the author for each lesson. The user predicts, reads and reviews the assistant's surrounding code until able to explain it. PLAN.md records the author of each file. Open design decisions, dependency selection and installation approval, large downloads, paid APIs and remote execution remain the user's decisions. The research UI keeps Mantine without handwritten CSS. Tests, fixtures, documentation and the public website stay with the assistant.
- 2026-11-27に利用者が教員の方針を報告しました。まずcommandlineとAPIで検証し、検証の後にUIを加えます。同じ日の最初の報告「UI画面は作らない」は利用者が訂正しました。人が使う入口はまず[CLI](docs/cli.md)で、他の人が書いたprogramも同じAPIを呼びます。React研究UI（[設計](docs/ui.md)）はCLIとAPIの検証の後に作ります。CLIの分担は2026-11-19の境界に従い、送信後の待機・回復・次のモデルの処理は本人、commandの枠組み・表示・終了codeはassistantです。この当てはめはassistantの提案で、利用者の確認待ちです。 / On 2026-11-27 the user reported the supervisor's direction: verify through the command line and API first, and add a UI after verification. The user corrected the first report of that day, which said no UI screen would be built. The human entry point is first the [CLI](docs/cli.md), and programs written by other people call the same API. The React research UI ([design](docs/ui.md)) is built after the CLI and API are verified. CLI work follows the boundary of 2026-11-19: waiting, recovery and next-model handling after a send belong to the user, and the command framework, output and exit codes to the assistant. That mapping is the assistant's proposal awaiting the user's confirmation.
- 2026-11-27に利用者は安全対策を強め、それを自分でも学ぶことを求めました。対策は[安全設計](docs/architecture.md#security)に層ごとに置き、各対策にtestを付けます。認証、認可、濫用の上限、保存dataの保護、注入への備え、browserの方針など、何を守りどこまで行うかの判断は本人が行います。middlewareは核心の知識として本人が書きます（利用者の指摘、2026-11-27）。重ねる順序と拒否する段は設計判断だからです。assistantは点検表と安全性のtestを書きます。testで確認していない対策を「安全」と表現しません。安全性の検査toolも依存であり、導入には許可が要ります。攻撃の検証は合成dataと自分のlocal環境だけで行います。 / On 2026-11-27 the user asked for stronger security and to learn it personally. Controls are layered in the [security design](docs/architecture.md#security), each with a test. The user decides what to protect and how far, including authentication, authorization, abuse limits, protection of stored data, defenses against injection and browser policy. The user also writes middleware as core knowledge (raised by the user, 2026-11-27), because chaining order and where a request is refused are design decisions. The assistant writes checklists and security tests. Never describe an untested control as secure. Security scanners are dependencies too and need authorization to install. Attack exercises use synthetic data and the user's own local environment only.
- 2026-11-27に利用者は、核心知識を自分で学べるよう分担の再整理を求めました。上の2026-11-19の「外周はassistant」の一覧に代えて、次の規則を使います。初めて出る型や概念は本人が書きます。HTTP handler、DTO変換、error envelope、middleware、起動と停止、migrationの実行、workerの最初の操作、CLIの `run` 関数と最初のsubcommand、manifest、job script、UIの雛形・入力処理・配信が含まれます。assistantが書くのは、本人が一度書いた型の繰り返し、test、fixture、test-only fake、検証harness、文書、公開websiteです。共同の回でも核心の部分は本人が先に書きます。各回の担当は[PLAN.md](PLAN.md#teaching-route)に記し、本人はいつでも変更できます。 / On 2026-11-27 the user asked for the division of work to be reorganized around learning the core knowledge personally. The following rule replaces the 2026-11-19 list of assistant-written surrounding code above. The user writes the first instance of every pattern and concept, including HTTP handlers, DTO mapping, the error envelope, middleware, startup and shutdown, the migration runner, the first worker operation, the CLI `run` function and first subcommand, the manifest, the job script, and the UI scaffold, input handling and serving. The assistant writes repetitions of a pattern the user has already written once, tests, fixtures, test-only fakes, verification harnesses, documents and the public website. In shared lessons the user still writes the core part first. [PLAN.md](PLAN.md#teaching-route) names the author of each lesson, and the user may change it at any time.
- 公開treeは現在資料に集中させます。発表archiveと生成sourceはignored `presentations/` のlocal専用で、stage/uploadしません。明示依頼された履歴置換の前にlocal backupを保持します。 / Keep the public tree focused on current material. Presentation archives and generation sources stay local under ignored presentations/; do not stage/upload them. Preserve local backups before explicitly requested history replacement.
